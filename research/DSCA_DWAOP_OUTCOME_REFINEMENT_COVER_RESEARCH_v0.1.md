## 1. Executive result

This investigation found that the existing DWAOP state-dominance idea needs a stricter pruning condition.

A single state with a smaller admissible possible-world set cannot, by itself, replace a broader state in a global search. It represents only a subset of the broader state's possibilities. Pruning the broad state on that basis can lose worlds that the smaller state does not cover.

The prototype therefore separates two concepts:

1. **Local outcome refinement:** a narrower, provenance-backed state can safely simulate a broader state's continuations *for worlds contained in the narrower state*.
2. **Complete refinement cover:** a collection of sibling states, generated by every outcome of one checked action from the same parent, can replace a broader state only when their disjoint world sets cover the broader state's entire possible-world set, every sibling safely simulates its continuations, and all branches remain feasible under the same hard resource budget.

The finite reference model implements this distinction and tests it against exhaustive policy enumeration on a deliberately small synthetic benchmark. During adversarial hardening, a `NaN` resource quantity was identified as capable of bypassing ordinary comparison-based budget checks; finite, non-negative validation and three regression tests were added.

**Result:** 26 tests passed; a generated test exhaustively checked 729 ordered pairs of deterministic three-world observation maps (covering all 25 ordered pairs of distinct, unlabeled set-partition shapes; the 729 maps include label-renamed duplicates). The synthetic fine-screening and coarse-screening root-action alternatives independently yield the same complete decision set and resource envelope. The candidate-state cover-pruner is tested separately; it is not yet integrated into the root planner, so this is not an end-to-end pruned-versus-unpruned search result. This supports the finite reference model's intended behaviour; it does not prove the general DWAOP theorem or validate a GDEC numerical certificate.

## 2. Why single-state dominance is insufficient

Let a state be represented in part by a possible-world set:

\[
S=(X, O, K, A, R, L),
\]

where:

- \(X\) is the set of possible worlds / admissible engineering states;
- \(O\) is the set of open assurance obligations;
- \(K\) is the set of capabilities currently available;
- \(A\) is the set of remaining eligible action identifiers;
- \(R\) is the cumulative additive resource ledger;
- \(L\) is the resident/live-artifact and peak-resource state.

Suppose \(X_+\subset X_-\). The smaller state \(S_+\) may be better informed than \(S_-\), but it covers only the worlds in \(X_+\). It does not establish what happens for worlds in \(X_-\setminus X_+\).

Therefore this pruning rule is unsound in general:

> Remove \(S_-\) whenever one state \(S_+\) has a smaller possible-world set and appears no more expensive.

The prototype includes a negative test: a single `fine_safe` state cannot prune the `coarse_both` state because the `unsafe_high` world is absent from `fine_safe`.

## 3. Local finite-horizon outcome simulation

### 3.1 State ordering

Write \(S_+\preceq S_-\) for a conservative local refinement relation. Necessary conditions in this prototype are:

\[
X_+\subseteq X_-,
\]

\[
O_+\subseteq O_-, \qquad K_-\subseteq K_+,
\]

and no-worse cumulative additive cost and peak/live memory:

\[
R_+\le R_-, \qquad L_+^{\rm peak}\le L_-^{\rm peak}.
\]

Both states must refer to the same specification and model identity. Their provenance must be checked: a root state starts from the full declared finite oracle universe; every subsequent state must exactly match a child produced by a validated parent/action/outcome transition. A caller cannot simply assert a smaller world set.

### 3.2 Action matching

For every action enabled in \(S_-\), the relation requires a matching enabled action in \(S_+\). The matching action must have the same:

- semantic/action signature;
- specification and model scope;
- capability preconditions and obligation preconditions;
- evidence contract and failure-handling contract;

and no greater upper-bound resource usage under the resource dimensions currently represented by the prototype.

The current implementation covers one additive resource (resource units, RU) and peak memory. It does not yet cover a general resource vector.

### 3.3 Observable outcome containment

An action produces a finite set of observable outcome cells. Labels are metadata; matching labels are not a semantic proof.

For every possible outcome cell \(C_i^+\) of the matching action from \(S_+\), there must be exactly one compatible outcome cell \(C_j^-\) from \(S_-\) such that:

\[
C_i^+\subseteq C_j^-.
\]

The corresponding successor states must preserve the refinement relation. This makes the relation conservative: a fine state may distinguish outcomes that the broad state groups together, but a coarse outcome cell that straddles two differently treated broad cells cannot be mapped to one successor.

The prototype rejects the latter case and also confirms that two different string labels are acceptable when the actual world-set containment is sound.

### 3.4 Local claim only

The local relation establishes a continuation-preservation result only over the smaller state’s worlds. It does **not** authorize deleting a broader state on its own.

## 4. Complete sibling refinement cover

Let \(S_-\) be a broader state with possible-world set \(X_-\). Consider an action \(a_+\) from the same parent state \(P\), producing sibling child states \(S_1^+,\ldots,S_n^+\), one for every observable outcome cell.

The group is a complete refinement cover of \(S_-\) only if all these conditions hold:

1. **Common parent:** every child is produced from the same canonical parent state \(P\).
2. **Same problem scope:** model, specification and assurance scope are identical.
3. **Complete outcome set:** every outcome transition of \(a_+\) from \(P\) is represented; no outcome is omitted.
4. **Disjoint world regions:** child world sets are pairwise disjoint under the deterministic partition model.
5. **Exact coverage:**
   \[
   X_- = \bigcup_{i=1}^{n} X_i^+.
   \]
6. **Local simulation:** for every sibling, \(S_i^+\preceq S_-\).
7. **Branch feasibility:** every sibling has a complete continuation under the same hard resource budget; the root action's own cost is included.
8. **Resource preservation:** cumulative additive resources are summed along a realised path; mutually exclusive branches use the worst realised branch; peak memory is a live-set high-water mark, not a sum of workspaces.

Only then may the broader continuation state be pruned in favour of the complete sibling cover.

A single narrow child, incomplete outcome list, duplicate/overlapping world coverage, invalid certificate, or unresolvable sibling branch disables the prune.

## 5. Conditional policy-preservation proposition

**Proposed finite-horizon proposition — not yet formally proved.**

Assume:

- the state possible-world sets are sound outer sets for the declared finite model;
- all state reductions are backed by checked action-outcome certificates and provenance;
- the sibling states form a complete refinement cover of the broader state;
- the local simulation relation holds recursively for every sibling and every continuation action;
- all observable outcomes are covered, and all mandatory obligations remain valid;
- action upper-bound resource semantics are sound and monotone under the matching relation;
- the policy horizon is finite, and unresolved states at the horizon are not treated as terminal.

Then every decision-complete finite-horizon continuation from the broader state can be simulated over the sibling refinement cover without weakening its terminal decision/assurance predicates or exceeding the matched worst-case resource envelope.

**Proof outline:**

For an arbitrary possible world in \(X_-\), exact sibling coverage places it in one and only one \(X_i^+\). From that sibling, the local simulation relation supplies a matching action for the broader policy's next action. Every outcome possible in the sibling maps to one compatible broader outcome cell, and the successor states preserve the relation. Induction over the finite remaining horizon gives a matching continuation. Since the sibling action tree includes all outcomes and each local action has no-worse resource bounds, path resource bounds are preserved under the declared aggregation operators.

The argument depends on the stated assumptions. It does not cover arbitrary cyclic policies, stochastic observation models, action failures not represented as branches, or numerical enclosures whose soundness has not been established.

## 6. Finite reference implementation

The standard-library-only prototype contains:

- a finite reference oracle mapping possible worlds to reference `ACCEPT` / `REJECT` decisions;
- trusted finite action semantics with applicability, observable outcome maps, typed obligation/capability effects, resource upper bounds, evidence/failure contract identifiers and proof identifiers;
- scoped outcome certificates and an action-contract verifier;
- evidence states with transition ancestry;
- a provenance verifier that reconstructs each child from its checked parent/action/outcome transition;
- finite AND-OR policy enumeration (every action outcome is an AND branch);
- additive RU and peak/live-memory accounting;
- finite-horizon local state refinement using outcome-cell containment;
- complete sibling refinement-cover checking and conservative pruning.

### Synthetic heat-QoI trace

The fixture has two abstract possible conditions:

- `safe_low` → reference decision `ACCEPT`;
- `unsafe_high` → reference decision `REJECT`.

Both screening actions consume 1 RU and produce 0.10 GB retained output:

- the fine screen separates `safe_low` and `unsafe_high` into two observable cells;
- the coarse screen reports one ambiguous cell containing both worlds.

Both paths then require a deterministic QoI-enclosure action (2 RU) and an independent certificate check (1 RU) on every resulting branch.

| Root policy | Complete outcomes | Total worst-case RU | Peak memory | Terminal decisions |
|---|---:|---:|---:|---|
| Fine screening | 2 | 4.0 | 0.90 GB | ACCEPT and REJECT |
| Coarse screening | 1, followed by certificate branches | 4.0 | 0.90 GB | ACCEPT and REJECT |

The complete fine sibling set covers the coarse state and each sibling locally simulates its continuations. The coarse state is prunable only when both fine siblings are present. The one-sibling negative test prevents pruning when the unsafe branch is missing.

These costs and decisions are synthetic oracle values; they are not measured GDEC execution results.

## 7. Executed tests

**Environment:** Python 3.13.5  
**Commands:** `python -m py_compile dwaop_outcome_refinement_oracle.py` and `python -m unittest -v dwaop_outcome_refinement_oracle.py`  
**Result:** 26 passed, 0 failed.

The 23 tests cover:

- valid action contracts and exact outcome coverage;
- wrong specification/model certificate scope;
- unknown, missing, overlapping or semantically incorrect outcome cells;
- forged obligation discharge and capability claims;
- understated RU, workspace, overlap and retained-memory upper bounds;
- non-finite (`NaN`) action costs, outcome-memory bounds and resource budgets;
- certificate memory claim weaker than the corresponding cell claim;
- invalid capability/obligation preconditions;
- rejection of a fabricated narrowed state without checked provenance;
- local outcome-cell refinement and reverse-relation rejection;
- different labels with valid region mapping;
- rejection when one outcome cell crosses two incompatible cells;
- failure-contract compatibility;
- complete sibling cover pruning and the negative single-sibling case;
- finite-horizon exhaustion returning non-refinement;
- complete branch handling, hard peak-memory rejection and worst-branch RU aggregation;
- separate root-action policy-frontier comparison for fine and coarse screening (not an integrated pruned-search comparison);
- exhaustive comparison of all 729 ordered pairs of deterministic three-world observation maps generated from three labels (all 25 unlabeled partition-shape pairs represented).

The 729-case test checks that the local relation agrees exactly with the set-containment oracle: every left outcome region must fit in exactly one right outcome region. These are 729 ordered pairs of label assignments/observation maps, not 729 distinct unlabeled partitions. For three worlds there are five distinct unlabeled set partitions and therefore 25 distinct ordered partition-shape pairs. It is exhaustive only for this three-world deterministic partition domain.

## 8. Limitations and non-claims

This prototype is deliberately much smaller than the DWAOP specification.

1. **No real engineering numerical certificate:** the certificates are finite-oracle records. They do not certify FEM, CFD, floating-point arithmetic, quadrature, mesh error or physical validity.
2. **No independent numerical checker:** contract verification compares artifacts to a synthetic trusted semantics table. That is a reference-model oracle, not an independent DAPC/VWEC proof checker.
3. **Deterministic observations only:** each abstract world maps to one observable action label. Nondeterministic observations, stochastic outcomes and measurement noise need a richer transition relation.
4. **Runtime failures are not represented as branches:** the failure-contract identifier is compared for compatibility, but timeouts, numerical breakdowns, device loss, retries and unsupported backend execution are not modeled as transition outcomes. The prototype must not be used to claim fail-safe completion under those conditions.
5. **Finite one-shot action portfolio:** actions are consumed after execution. Cyclic/repeated action planning, fairness and termination arguments are out of scope.
6. **Resource model restricted:** one additive resource (RU) and peak memory are represented. CPU time, elapsed time, GPU time, transfer costs, energy, parallel makespan and contention are not.
7. **Finite horizon only:** a nonterminal state at the horizon is not accepted as a refinement proof. No general termination or optimality result is claimed.
8. **No search scalability result:** no large generated contingent planning graph, realistic solver portfolio or measured computation saving has been tested.
9. **No integrated planner-pruning result:** the cover-pruner is exercised on a finite candidate set, while root-action policies are enumerated separately. The general AND-OR search does not yet invoke this pruner, and no arbitrary generated graph comparison has been completed.
10. **No novelty conclusion:** local simulation, outcome containment, proof-carrying planning and adaptive numerical computation all have prior-art overlap. This test does not establish a novel algorithm or patentability.

## 9. Next research gate

The next test campaign should:

1. generate small action graphs with 3–5 worlds, mixed fan-out, reconvergence and multiple levels of refinement;
2. integrate complete refinement-cover pruning into a root-level finite planner, then compare pruned and unpruned complete policy Pareto frontiers against exhaustive enumeration for every generated case;
3. introduce action failures, timeout/retry outcomes and model invalidation as explicit branches;
4. test resource accounting with multiple additive dimensions and a more explicit live-artifact model;
5. add mutation tests that corrupt outcome coverage, scope, proof IDs, obligation effects, action preconditions, successor maps and branch resource totals;
6. only then consider an independently implemented finite checker and an abstract proof formalisation.

The first numerical-engineering connection remains a later gate: one steady linear heat-conduction problem with a linear QoI and a genuinely guaranteed, independently checked output-error enclosure. The DWR estimator in current GDEC evidence must not be re-labelled as such a bound.
