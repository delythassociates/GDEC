## Section A: Repository Baseline & Audit Mandate

Following Phase 4.1.1 remediation, an independent software and numerical methods audit reviewed commit `65bfe28a12b49733e14ec1a137ffb5766c9a15d6`. While matrix diagnostics and Krylov stability were substantially improved, the audit identified critical remaining failure modes:
1. `LinearElasticitySolver.solve()` defaulted to `caller_certified_spd=True`, silently bypassing upfront positive-definiteness verification for ordinary FEM calls even on unconstrained or roller-constrained models with rigid-body modes.
2. `ConjugateGradientSolver.solve()` used an absolute check `lambda_min <= 0.0` rather than a scale-aware relative threshold, risking accepting numerically near-singular matrices with tiny positive eigenvalues.
3. The base `Preconditioner` class declared `is_spd = True`, allowing unverified custom subclasses to claim SPD compatibility by default. Furthermore, `AMGPreconditioner` accepted arbitrary kwargs without verifying symmetric cycle or smoother compatibility.
4. `compute_symmetry_defect()` used an absolute denominator floor `eps = 1e-15`, distorting relative symmetry calculations when matrices were scaled to small values.
5. `analyze_stiffness_matrix()` passed nonsymmetric matrices to symmetric eigensolvers (`eigsh`) or discarded imaginary eigenvalue components in dense solves.
6. Documentation files contained the stale tolerance formula $\text{rtol} = \min(10^{-4}, 0.1 \times \text{acc}/100)$, unverified universal QoI accuracy claims, and stale Cholesky references.

This hardening pass (Phase 4.1.2) systematically resolves each issue.

## Section B: SPD Certification Interface Changes

### The Flaw
In `LinearElasticitySolver.solve()`, the default parameter was:
```python
caller_certified_spd: bool = True  # Flawed default
```
This inverted the fail-safe principle: an ordinary user calling `solver.solve(mesh, loads, bcs, solver_type="cg")` implicitly bypassed upfront spectral verification, even if boundary conditions failed to eliminate all rigid-body modes.

### The Remediation
1. **Default Inverted to Fail-Closed:**
   In `src/gdec/fem/elasticity.py`:
   ```python
   caller_certified_spd: bool = False  # Fail-safe default
   ```
2. **Explicit Caller Assertion:**
   Skipping the upfront eigenvalue check requires explicit opt-in: `caller_certified_spd=True`. The docstring explicitly states that this parameter is a **caller assertion** based on structural mechanics or domain physics, **not** a certificate generated by the solver.
3. **No False Inferences:**
   Positive definiteness is neither inferred from symmetric elasticity assembly nor from positive diagonal entries.
4. **Direct Solver Performance Preserved:**
   Direct sparse solves (`solver_type="direct"`, SuperLU) do not execute eigenvalue checks, preserving their performance (<1 ms on small grids; 46 ms at $N=9,120$).
5. **Runtime Curvature vs Global SPD Proof:**
   A regression test (`test_direct_cg_indefinite_matrix_positive_eigenspace_rhs`) proves that an indefinite matrix $A = \begin{bmatrix} 2 & 3 \\ 3 & 2 \end{bmatrix}$ (eigenvalues $-1$ and $+5$) with right-hand side $b = (1, 1)^T$ in the positive eigenspace generates strictly positive curvature ($\kappa_k > 0$) throughout all iterations, terminating with zero residual after 1 iteration. This demonstrates mathematically why runtime curvature checks alone are **not** a global proof of positive-definiteness.

## Section C: Relative Eigenvalue Threshold Verification in CG

### The Flaw
`ConjugateGradientSolver.solve()` previously evaluated `if lambda_min <= 0.0`. If a singular elasticity system with rigid-body modes produced an eigenvalue of $+1.29 \times 10^{-6}$ while $\lambda_{\max} \approx 10^{10}$, the naive $> 0$ check treated it as positive-definite.

### The Remediation
In `src/gdec/fem/solvers/iterative.py`, `ConjugateGradientSolver.solve()` implements scale-aware relative thresholding consistent with `analyze_stiffness_matrix()`:
$$\lambda_{\text{scale}} = \max(|\lambda_{\min}|, |\lambda_{\max}|, \epsilon_{\text{tiny}})$$
$$\tau_{\text{null}} = 10^{-10} \quad (\text{configurable via } \texttt{null\_tol})$$

The solver distinguishes four distinct spectral categories:
1. **Indefinite:** $\lambda_{\min} < -\tau_{\text{null}} \lambda_{\text{scale}} \implies$ Raises `ValueError("Matrix is not positive-definite: matrix is indefinite...")`.
2. **Non-Positive:** $\lambda_{\max} \le \tau_{\text{null}} \lambda_{\text{scale}} \implies$ Raises `ValueError("Matrix is not positive-definite: largest algebraic eigenvalue is non-positive...")`.
3. **Numerically Near-Singular / Null Modes:** $|\lambda_{\min}| \le \tau_{\text{null}} \lambda_{\text{scale}} \implies$ Raises `ValueError("Matrix is not positive-definite: matrix is numerically near-singular or possesses unconstrained null modes...")`.
4. **Clearly Positive-Definite:** $\lambda_{\min} > \tau_{\text{null}} \lambda_{\text{scale}} \implies$ Verification succeeds.

Both dense ($N \le 300$) and sparse ($N > 300$) paths apply this exact relative threshold convention, guaranteeing consistent rejections across problem dimensions and arbitrary scalar scalings.

## Section D: Preconditioner Compatibility & AMG Configuration

### Fail-Closed Base Preconditioner Contract
In `src/gdec/fem/solvers/iterative.py`, the abstract base class `Preconditioner` now defines:
```python
@property
def is_spd(self) -> bool:
    """Base implementation fails closed (returns False)."""
    return False
```
Any unknown custom preconditioner that inherits from `Preconditioner` without explicitly implementing and verifying `is_spd` returns `False` and is rejected by ordinary CG with a clear diagnostic.

### Preconditioner Status Matrix
| Preconditioner | `is_spd` Declaration | Verification Mechanism |
|---|---|---|
| `IdentityPreconditioner` | `True` | Analytically $M = I > 0$. |
| `JacobiPreconditioner` | `True` | Validated in `__init__`: all $K_{ii} > 0$ and finite. |
| `IncompleteCholeskyPreconditioner` | `True` | Validated in `__init__`: Cholesky factorization completed with positive pivots. |
| `ILUPreconditioner` | `False` | Unsymmetric factors $L U$; strictly rejected by CG compatibility gate. |
| Custom Preconditioner | `False` (Default) | Fails closed unless explicitly overridden. |
| `AMGPreconditioner` | `True` (Conditional) | Verified ONLY for supported symmetric configurations. |

### AMG Verification Contract
In `AMGPreconditioner`:
- Supported cycles: `"V"`, `"W"`.
- Supported smoothers: `"gauss_seidel"`, `"symmetric_gauss_seidel"`, `"jacobi"`, `"block_gauss_seidel"`, `None`.
- `_verify_spd_configuration()`: Requires `symmetric=True`, supported cycle, supported smoother, and no unverified arbitrary kwargs.
- Unsupported configurations (e.g., `symmetric=False` or unsymmetric smoothers) evaluate `is_spd = False` and are rejected if passed to ordinary CG.
- Missing PyAMG package raises clear `ImportError` with installation instructions.

## Section E: Symmetry Scale-Invariance Tests

### The Flaw
`compute_symmetry_defect(K, eps=1e-15)` used an absolute denominator floor:
$$\text{denom} = \max(\|K\|_F, 10^{-15})$$
For matrices with small physical norms (e.g., micro-mechanics where $\|K\|_F \approx 10^{-18}$), the denominator was artificially clamped to $10^{-15}$, causing asymmetric matrices with defect $\|K - K^T\|_F \approx 10^{-26}$ to yield $\delta_{\mathrm{sym}} \approx 10^{-11} < 10^{-10}$, falsely classifying an asymmetric matrix as symmetric!

### The Remediation
The denominator floor is eliminated:
$$\delta_{\mathrm{sym}} = \frac{\|K - K^T\|_F}{\|K\|_F} \quad \text{for } \|K\|_F > 0$$
For the exact zero matrix ($\|K\|_F == 0$), $\delta_{\mathrm{sym}} \equiv 0.0$.

### Verification Evidence
In `test_symmetry_defect_scale_invariance_across_24_orders`, an asymmetric matrix $K = \begin{bmatrix} 1 & 10^{-8} \\ 0 & 1 \end{bmatrix}$ is multiplied by scaling factors spanning 28 orders of magnitude ($c \in [10^{-14}, 10^{14}]$):
- At all scales, $\delta_{\mathrm{sym}} = 7.0710678 \times 10^{-9}$ to machine precision ($< 10^{-12}$ relative discrepancy).
- Matrix is classified as asymmetric across all scales without distortion.
- Exact zero matrix returns $0.0$.

## Section F: Nonsymmetric Matrix Handling in Diagnostics

### The Flaw
`analyze_stiffness_matrix()` previously:
1. In dense mode, computed eigenvalues using general `la.eigvals()`, silently discarded imaginary parts via `np.real()`, and classified the matrix as positive-definite.
2. In sparse mode, passed nonsymmetric matrices to `spla.eigsh()`, which assumes a symmetric/Hermitian operator, causing undefined behavior or using only one triangle.

### The Remediation
1. **Symmetry Precondition:** Matrix symmetry ($\delta_{\mathrm{sym}} \le \text{sym\_tol}$) is established before attempting any SPD classification.
2. **Sparse Protection:** If `is_symmetric is False`, ARPACK `spla.eigsh` is **never** called. The diagnostic marks `eigenvalue_method = "skipped_nonsymmetric"` and emits a clear warning.
3. **Dense Handling:** General eigenvalues are evaluated via `la.eigvals()`. If non-trivial imaginary components exist, a complex-spectrum warning is recorded. Imaginary parts are **never** discarded to claim positive-definiteness.
4. **Eligibility:** Both `is_positive_definite` and `is_cg_eligible` are strictly set to `False`.

Verified in `test_nonsymmetric_matrix_no_symmetric_eigensolvers` for dense and sparse matrices ($N=500$).

## Section J: Remaining Limitations & Honest Scientific Scope

To preserve scientific integrity, the following limitations are explicitly documented:
1. **CPU 2D Linear Elasticity Scope:** GDEC v0.2.2 is implemented exclusively for 2D linear elastostatics with conforming $P_1$ triangular elements. 3D continuum mechanics and non-linear material models are planned for Phase 7.
2. **Direct Solver Default:** The sparse direct solver (`scipy.sparse.linalg.factorized` via SuperLU) remains the production default. Automatic solver selection is not active. Iterative solvers are exposed as experimental opt-in features.
3. **DWR Certified Bounds:** DWR error estimates and Richardson extrapolation provide asymptotic verification; guaranteed certified upper bounds require analytical domain trace constants ($C_{\text{trace}}$), planned for Phase 7.
4. **PyAMG Optional Dependency:** `pyamg` is not installed by default in standard GDEC CI environments; `AMGPreconditioner` acts as an optional interface that fails closed when unavailable or unverified.
